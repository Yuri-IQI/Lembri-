1. Visão Geral e Papel do Wearable

O Lembri Wearable é uma aplicação nativa para smartwatches com Wear OS (desenvolvida em Kotlin com Jetpack Compose for Wear OS). O propósito principal do aplicativo no relógio é oferecer ao usuário:

  • Acesso Instantâneo e Desembaraçado: Visualização de lembretes e tarefas no pulso sem a necessidade de retirar o celular do bolso;
  • Conclusão em Um Toque: Marcar lembretes como concluídos diretamente na tela redonda do relógio com resposta visual imediata (checkmark ✓);
  • Sincronização em Segundo Plano: Notificações e lembretes são entregues no relógio mesmo que a tela do aplicativo no celular esteja fechada (via WearableListenerService);
  • Operação Offline Resiliente: O relógio guarda a agenda e os feitos no aparelho, e os eventos gravados como DataItems chegam ao celular quando a conexão for restabelecida.

2. Arquitetura do App no Relógio (WearableAPP)

O WearableAPP adota o padrão MVVM (Model-View-ViewModel) com Unidirectional Data Flow (UDF) e injeção manual de dependências via AppContainer:

WearableAPP/app/src/main/java/com/borabill/lembriwearable/
├── LembriWearApplication.kt       # Application class: instancia o AppContainer singleton
├── di/
│   └── AppContainer.kt            # Cria a instância única de AgendaRepository
├── data/
│   ├── model/                     # AgendaRelogio, LembreteAgenda e EventoRelogio + JSON
│   ├── comunicacao/
│   │   ├── ContratoComunicacao.kt # Constantes de paths e ids de exercício
│   │   ├── CelularDataSource.kt   # Lê a agenda, grava eventos e checa a conexão
│   │   └── LembriWearListenerService.kt # Recebe a agenda em segundo plano
│   └── repository/
│       ├── AgendaRepository.kt    # Fonte da verdade em StateFlow para a UI
│       └── FeitosLocais.kt        # Feitos e desfazer pendente (SharedPreferences)
└── presentation/
    ├── MainActivity.kt            # Ponto de entrada nativo
    ├── navigation/                # Rotas e SwipeDismissableNavHost
    ├── inicio/                    # Próximo lembrete, "Mais tarde" e rodapé de conexão
    ├── sequencia/ e guardar/      # Exercícios do relógio
    ├── resumo/                    # Resultado do exercício
    ├── comum/                     # Componentes reutilizados
    └── theme/                     # Cores, tipografia e dimensões

Destaques de Implementação da UI no Relógio:

  • ScreenScaffold & ScalingLazyColumn: Layout padrão do Wear OS Material 3, com lista que escala os itens nas bordas da tela redonda;
  • Feedback Visual Imediato: O botão Feito vira Desfazer por 10 segundos. Só depois disso o evento é gravado para o celular.

3. Fluxo de Comunicação e Contrato de Dados

A sincronização é bidirecional e ocorre através da Wearable Data Layer API do Google Play Services:

Celular (MobileAPP - React Native)                  Relógio (WearableAPP - Kotlin)
─────────────────────────────────                  ──────────────────────────────
[Lembretes ou feitos mudam]
          │
          ▼
useSincronizarRelogio → publicarAgendaAtual()
          │
  /lembri/agenda (DataItem) ───────────────────────▶ LembriWearListenerService
  { v, geradoEm, lembretes: hoje + amanhã }                 │
                                                            ▼
                                                    AgendaRepository.receberAgenda()
                                                            │
                                                            ▼
                                                    StateFlow atualiza UI
                                                            │
                                         [Feito depois de 10 s ou exercício concluído]
                                                            │
EventosRelogioService ◀── /lembri/eventos/<uuid> ──────────┘
          │                (DataItem)
          ▼
processarEventos(): aplica nas stores → cancela avisos → publica agenda → apaga evento

O serviço aciona uma tarefa headless, então funciona com o processo do app encerrado e também com ele aberto. Ao abrir o app, os eventos pendentes são lidos de novo, como garantia. Processar o mesmo evento duas vezes não duplica nada.

Contrato Compartilhado e Espelhado:

O contrato é rigorosamente sincronizado entre os dois projetos:

  • Mobile (TypeScript): MobileAPP/src/services/wear/contrato.ts
  • Wearable (Kotlin): WearableAPP/.../data/comunicacao/ContratoComunicacao.kt
Constante Valor Finalidade
CAPABILITY_WEAR "lembri_wear" Capability anunciada pelo relógio em res/values/wear.xml
PATH_AGENDA "/lembri/agenda" Celular publica os lembretes de hoje e amanhã (um único DataItem)
PATH_EVENTOS "/lembri/eventos/<uuid>" Relógio grava cada Feito ou resultado de exercício; o celular apaga depois de aplicar

4. Módulo Nativo Expo (MobileAPP/modules/wear-connector)

Para permitir que o React Native 0.88 / Expo SDK 58 se comunique com as APIs nativas do Android, foi criado o módulo nativo customizado wear-connector:

  • WearConnectorModule.kt: Transporte genérico em Kotlin (publicarDado, listarDados, apagarDado, listarRelogios) sobre Wearable.getDataClient, Wearable.getCapabilityClient e Wearable.getNodeClient;
  • EventosRelogioService.kt: Escuta DATA_CHANGED em /lembri/eventos e inicia a tarefa headless lembri-eventos-relogio;
  • with-shared-debug-keystore.js: Plugin de configuração do Expo que garante que o APK de debug do celular seja assinado com a mesma chave (~/.android/debug.keystore) do Android Studio, requisito obrigatório para o Google Play Services parear os apps;
  • Fallback Resiliente: Caso a capability não propague de imediato no emulador, o módulo detecta os nós pareados diretamente via NodeClient.getConnectedNodes().

5. Ergonomia e Acessibilidade no Pulso (Wear OS AAA)

Assim como o aplicativo mobile respeita WCAG 2.2 AAA, o app do relógio foi arquitetado com base em princípios rigorosos de usabilidade e ergonomia para wearables:

  1. Contraste OLED Máximo: Fundo preto puro (#000000) com textos em alto contraste para economia de bateria e legibilidade sob luz solar direta;
  2. Alvos de Toque no Pulso: Botões ocupam a largura total da tela redonda (fillMaxWidth) e utilizam transformedHeight para evitar toques incorretos;
  3. Hierarquia Tipográfica Clara: Título em negrito com horário destacado e indicador textual explícito de status ("Concluído ✓");
  4. Prevenção de Toques Acidentais: Itens já concluídos tornam-se inativos (enabled = false) para prevenir cliques redundantes no pulso;
  5. Sem Limites de Tempo Inflexíveis: As notificações e lembretes permanecem disponíveis na lista do relógio até que o usuário decida interagir.

Para executar e depurar a solução completa integrada, utilize dois terminais em PowerShell devido às exigências distintas de JDK:

Aplicação JDK Necessário Comando de Inicialização

Terminal 2: MobileAPP JDK 17 (C:\Program Files\Java\jdk-17) $env:JAVA_HOME = "C:\Program Files\Java\jdk-17"; npx expo run:android --device Pixel_10_Pro
